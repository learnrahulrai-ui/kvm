CORE FAILURE, NOT AN ERROR-RETURN EXERCISE:
vhost_client_sync_dirty_bitmap converts a dirty range from a vhost-registered memory region into QEMU guest address space incorrectly. Mapping the wrong range can index beyond valid dirty bitmap memory.
CALL / DATA / STATE PATH:
migration snapshot -> vhost_client_sync_dirty_bitmap -> cpu_physical_memory_set_dirty with wrong range -> cpu_physical_memory_get_dirty -> QEMU SIGSEGV
REPRODUCTION PROCEDURE AND REQUIRED RESOURCES:
Use two disposable old QEMU VMs, live migrate with vhost=on. Original report shows a GDB call stack in cpu_physical_memory_set_dirty (cpu-all.h:909) and vhost_client_sync_dirty_bitmap (hw/vhost.c:71); verify region bounds/offsets at those frames. QEMU builds from 2011 require older toolchains; modern QEMU does not prove this legacy failure.
FAILURE SIGNAL AND CONTROL:
