B03 | Nested guest hangs after migration restores L2 TSC as L1 TSC
PUBLIC ORIGIN YEAR: 2020
EVIDENCE STATUS: CONFIRMED_PATCH_TESTED_AUTHOR
CAN TRY ON SECOND LAPTOP: MODERATE_NESTED_AMD
LOCAL REPRODUCED: NO_REPRO_RUN
CORE FAILURE, NOT AN ERROR-RETURN EXERCISE:
MSR_IA32_TSC read for host migration returned host+L1+L2 offsets, while host write restored value as L1 time; jump backward broke APIC deadline progress, especially on AMD SVM.
OBSERVED OPERATION THAT MATTERS:
Host Linux revision before 2020 fix; nested KVM L1 and running L2; migrate L1 by savevm stream or file and restore while L2 running.
FUNCTION-TO-FUNCTION REASONING PATH:
L2 executing -> QEMU reads MSR_IA32_TSC -> receives L2-relative value -> migration save -> L1 restore interprets value as L1 clock -> backward jump -> APIC deadline never fires -> L2 hangs
ORIGINAL REPORT / PATCH (READ BODY NOT TITLE): https://lkml.iu.edu/2009.2/06466.html
FIX OR UNCERTAINTY: 2020 KVM host_initiated MSR handling returns L1-relative TSC for host-initiated read
REPRODUCTION PROCEDURE AND REQUIRED RESOURCES:
Use an isolated L0 VM with older kernel and nested SVM exposed; L1 KVM guest executes tight L2 loop while L1 migration stream saved/loaded. Compare clock monotonicity and timer expiry after restore. Requires real nested virtualization support.
MEANINGFUL SUCCESS/FAILURE SIGNAL:
L2 timer stalls or hangs pre-fix; fix makes host read reflect L1 rather than L2 time
