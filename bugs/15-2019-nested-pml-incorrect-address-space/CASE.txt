B15 | KVM nested dirty logging records L2 addresses where L1 addresses are required
PUBLIC ORIGIN YEAR: 2019
EVIDENCE STATUS: CONFIRMED_KVM_PATCH_WITH_REGRESSION_TEST
CAN TRY ON SECOND LAPTOP: REQUIRES_INTEL_VMX_PML_NOT_AMD_RYZEN
LOCAL REPRODUCED: NO_REPRO_RUN
CORE FAILURE, NOT AN ERROR-RETURN EXERCISE:
Hardware EPT page-modification logging reports L2 guest-physical page numbers. When KVM uses shadow paging to run L2 under L1 and must record dirty memory for migration of L1, these numbers are NOT in L1 guest-physical address space; copying them into L1's dirty map loses the actual modified L1 pages. Correct mode has to force shadow-SPTE write protection to trap writes and derive the L1 address.
OBSERVED OPERATION THAT MATTERS:
L2 writes -> hardware PML records L2 GPA -> KVM dirty bitmap belongs to L1 GPA -> wrong bit -> migration omits modified L1 page -> restored guest has old content
FUNCTION-TO-FUNCTION REASONING PATH:
L2 writes -> hardware PML records L2 GPA -> KVM dirty bitmap belongs to L1 GPA -> wrong bit -> migration omits modified L1 page -> restored guest has old content
