B16 | Nested AMD SVM migration loses pending-run status, discards already saved interrupt injection
PUBLIC ORIGIN YEAR: 2021
EVIDENCE STATUS: CONFIRMED_AUTHOR_REPRO_REVIEW_CORRECTED_HYPOTHESIS
CAN TRY ON SECOND LAPTOP: MODERATE_NESTED_AMD_SVM_WITH_VERSION_PINNED_L0
LOCAL REPRODUCED: NO_REPRO_RUN
CORE FAILURE, NOT AN ERROR-RETURN EXERCISE:
The nested VMCB containing pending L1->L2 interrupt data DID survive migration. The 'nested_run_pending' state flag was saved but not restored. On destination a spurious nested exit erased pending interrupt injection before L2 entry. Because interrupt never arrived, I/O-intensive L2 guest hung. Original author's first proposed remedy to copy injections was mistaken; reviewed v2 restored the missing flag.
OBSERVED OPERATION THAT MATTERS:
L1 requests L2 VMRUN with event_inj=0x80000036 -> L1 migration saves VMCB and flag -> target restores VMCB but omits nested_run_pending -> unwanted nested vmexit clears event_inj -> L2 waits for missing interrupt -> L2 hangs
