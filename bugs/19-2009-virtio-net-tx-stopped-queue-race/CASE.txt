END-USER FAILURE: virtio_net completed transmit queue can remain stopped with no pending work
CORE FAILURE, NOT AN ERROR-RETURN EXERCISE:
xmit_tasklet frees completed TX buffers but does not wake the stopped transmit queue, so the virtqueue has space but no producer can resume transmission.
CALL / DATA / STATE PATH:
guest netdev TX queue becomes stopped -> host completes packets -> xmit_tasklet reclaims descriptors -> queue still marked stopped -> guest sends no more packets
REPRODUCTION PROCEDURE AND REQUIRED RESOURCES:
In a disposable old Linux guest use virtio-net, sustained TCP streams (iperf/netperf), monitor /proc/net/dev and TX queue state; reporter observed network disappearing. Trace tasklet and netif_wake_queue; compare with patch. Note this TX fix does NOT address other RX stalls reported in later comments.
FAILURE SIGNAL AND CONTROL:
Network TX stops even though completions freed descriptors; patched driver restarts TX after completion.
MANUAL INPUT AND QUESTION:
CONSTRUCTED: ring occupancy reaches capacity 256, completes 64 and frees them, but queue_stopped remains true. Derive descriptor availability and compare against driver's paused state.
