B08 | QEMU shared-page postcopy hangs with all memory already received
PUBLIC ORIGIN YEAR: 2026
EVIDENCE STATUS: CONFIRMED_UPSTREAM_PATCH_WITH_THREAD_TRACES
CAN TRY ON SECOND LAPTOP: SOFTWARE_HEAVY_VHOST_USER
LOCAL REPRODUCED: NO_REPRO_RUN
CORE FAILURE, NOT AN ERROR-RETURN EXERCISE:
Request insertion uses client_addr belonging to external vhost-user backend address space; deletion uses QEMU host process address. Same backing page does not mean same virtual key.
OBSERVED OPERATION THAT MATTERS:
Postcopy migration with postcopy-preempt and vhost-user backend faults on a not-yet-received shared page; a request entry remains after placement.
FUNCTION-TO-FUNCTION REASONING PATH:
postcopy_request_shared_page -> migrate_send_rp_req_pages inserts backend VA -> qemu_ufd_copy_ioctl removes QEMU VA -> lookup misses -> page_requested_count stays positive -> cleanup waits forever
ORIGINAL REPORT / PATCH (READ BODY NOT TITLE): https://www.mail-archive.com/qemu-devel@nongnu.org/msg1221024.html
FIX OR UNCERTAINTY: 2026 patch inserts qemu_ram_get_host_addr(rb)+aligned_rbo as key; backend wake still uses client VA
