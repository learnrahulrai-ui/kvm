06. WHY IDENTICAL PAGES CAN BECOME ONE FRAME. For each pair of guest physical pages with identical bytes, KSM may replace two mergeable host backing pages with one physical KSM page and write-protect their mappings; a guest write then must create an independent page to preserve the second guest's view. KSM is a Linux feature and not the exact ESX page-sharing implementation. In QEMU the -object memory-backend-ram,...,merge=on option marks backing as mergeable; actual merging additionally requires KSM daemon run=1 and compatible pages. Read /sys/kernel/mm/ksm/run, pages_shared, pages_sharing, pages_unshared, full_scans. pages_shared counts shared PAGE OBJECTS; pages_sharing counts additional mappings and is a primary approximation of saved base pages. The global counters include every eligible process, not just these two VMs. Use actual /proc/$pid/ksm_stat where available for process-scoped evidence. Read /sys/kernel/mm/ksm and KSM documentation before interpreting the numbers.

09. BALLOONING IS A PROTOCOL, NOT FREEING A HOST POINTER. Linux guest virtio-balloon driver agrees to give up host backing by allocating/pinning some of its OWN pages and reporting their physical page identifiers to the virtual device. Guest victim selection and host resource control are separate; a balloon target expresses a request, not immediate successful reclamation. Confirm guest driver present: inside guest inspect lsmod | grep virtio_balloon and dmesg for balloon. From host run python3 scripts/qmp.py /tmp/ws-vms01/a.qmp query-balloon; then python3 scripts/qmp.py /tmp/ws-vms01/a.qmp balloon 671088640. 671088640 bytes=640MiB logical target, down from 768MiB; the difference is 128MiB. Guest response is asynchronous; compare query-balloon several times and /proc/meminfo inside the guest. QEMU query-balloon.actual denotes logical VM memory (not an independent RSS metric). The script restricts requested logical memory between 256 and 768 MiB, but the user must stop workload before OOM. Restore with balloon 805306368 (768 MiB). Compare current KSM pages_sharing and actual host process RSS. Do not claim every requested balloon page physically disappears or that all additional storage I/O is caused by reclaim.

10. SAMPLE ACTIVE MEMORY. First define activity in the SAME terms as 2002 ESX §5.3: a virtual-physical page accessed during a VM-execution-time interval. ESX randomly selected 100 pages per 30 second period, removed their cached translations and counted first subsequent accesses. It maintained THREE estimates: slow exponential mean, fast exponential mean, current-sample-adjusted fast mean, and used their maximum. Current lab does NOT replace host KVM page tables to repeat ESX's transparent interception. Implement the next student-owned research stage inside a disposable guest or via KVM notifier/bpf trace: choose a set of guest memory pages, force or detect accesses, measure true accessed fraction, then compare an independent sample. Software example: n=100 and touched=35 gives estimate 0.35, standard error sqrt(0.35*0.65/100)≈0.0477 under independent Bernoulli assumptions. Periodic touching or huge translations breaks assumptions; TLB invalidation adds overhead. Do not equate soft-dirty writes with all page reads. Actual hardware accessed-bit sampling needs the architecture-specific invalidation ordering.

11. THE IDLE TAX POLICY IS AN EXACT FORMULA. ESX 2002 §5.2 defines shares S, allocated pages P, active fraction f, tax fraction τ. Derive k=1/(1−τ) then adjusted shares per page ρ=S/[P(f+k(1−f))]. Run ./build/idle_tax 100 100 0.25 50 50 0.75 0.75. With τ=.75, k=4; VM A denominator=100(.25+4*.75)=325, ρA≈0.307692; VM B denominator=50(.75+4*.25)=87.5, ρB≈0.571429. Lower ρ is the FIRST reclaim candidate in a simplified competition with no reservation binding; it does not identify a specific guest page. These values are CONSTRUCTED. TASK: on paper derive the formula, then choose a candidate; rerun with τ=0 and observe both ratios equal 1. REAL host policy not implemented: Linux memory.low/high/min/max do not duplicate this ESX share tax mechanism. The code is a calculator, not an AHV policy.

13. REUSE DISTANCE BEFORE SHARDS. In traces/six-blocks.txt the observed accesses are A,B,C,A,B,A. The reuse distance of a block is the number of DISTINCT block identities accessed since its previous access. Before the first A/B/C all are cold misses. The second A has B,C between -> d=2; the second B has C,A between -> d=2; the final A has B between -> d=1. A size-1 LRU cache misses 6 of 6; size-2 misses 5; size-3 misses 3. Run ./build/mrc traces/six-blocks.txt 1000 and verify rows 1,0,6 ; 2,1,5 ; 3,3,3. This is an exact baseline for the small trace, not a production efficient implementation; it scans prior identities and has a 4096-unique-ID cap. Connect to assignments/20-cmu-15213-cache-lab, but LRU stack MRC is not a direct-mapped cache simulation.
