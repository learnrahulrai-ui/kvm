Lottery scheduling
GOAL: Divide CPU grants among runnable programs in proportion to their tickets.
CAUSE: runnable -> tickets -> draw -> CPU
DATA: proc.state | proc.tickets | proc.ticks | proc.pid
CORRECTION: changing set -> wrong draw -> locked set -> same winner
INTERVIEWER TRAP: sleeping task -> ticket pool -> runnable set -> CPU
MANUAL CALCULATION: Tickets 30:20:10 give 30/60=50%,20/60=33.33%,10/60=16.67%. The distribution is probabilistic, not an exact 60-quantum outcome.
EVIDENCE STATUS: Constructed scheduling race; no exact upstream incident established.
PRIMARY/RELEVANT SOURCE: https://www.cs.virginia.edu/~cr4bd/4414/F2019/lottery.html
