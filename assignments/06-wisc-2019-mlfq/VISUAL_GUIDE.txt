Multiple-level feedback queue
GOAL: Prefer interactive work without allowing continuously running tasks to starve other work.
CAUSE: ready tasks -> queues -> priority -> CPU
DATA: queue.ready | queue.level | queue.ticks | queue.wait
CORRECTION: strict priority -> starvation -> aging rule -> eventual service
INTERVIEWER TRAP: busy queue -> quiet queue -> waiting work -> no service
MANUAL CALCULATION: If a high queue stays nonempty, strict top-queue service can give a lower queue zero dispatches without a promotion rule.
EVIDENCE STATUS: No exact code defect verified; related policy counterexample, not an upstream bug.
PRIMARY/RELEVANT SOURCE: https://pages.cs.wisc.edu/~shivaram/cs537-sp19/p2b.html
