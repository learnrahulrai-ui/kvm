Stride scheduling
GOAL: Choose the runnable program with the least accumulated service-time score.
CAUSE: tickets -> stride -> pass -> CPU
DATA: proc.tickets | proc.stride | proc.pass | proc.state
CORRECTION: old pass -> early grants -> normalized pass -> fair grant
INTERVIEWER TRAP: pairwise fair -> many clients -> short window -> large gap
MANUAL CALCULATION: With tickets 100:1 and scale 10000, strides are 100 and 10000. Pairwise lag does not prove global one-quantum error across 101 clients.
EVIDENCE STATUS: Published counterexample in Waldspurger's 1995 thesis; not a software defect.
PRIMARY/RELEVANT SOURCE: https://publications.csail.mit.edu/lcs/pubs/pdf/MIT-LCS-TR-667.pdf
