Scheduling system calls
GOAL: Expose process information to user space without observing a mixed process-table state.
CAUSE: user request -> syscall -> proc table -> user data
DATA: proc.pid | proc.state | proc.tickets | proc.ticks
CORRECTION: mutable scan -> mixed values -> locked snapshot -> consistent copy
INTERVIEWER TRAP: process exits -> scan starts -> scan ends -> stale rows
MANUAL CALCULATION: A scan of three process records must treat the snapshot as one state; the number of records is not a lock guarantee.
EVIDENCE STATUS: Real assignment warns that process-table walks require locking; no exact reported bug.
PRIMARY/RELEVANT SOURCE: https://www.cs.virginia.edu/~cr4bd/4414/F2019/lottery.html
