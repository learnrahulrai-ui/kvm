Virtual CPU and memory balancing
GOAL: Use changes in counters to decide CPU placement and memory allocation across running VMs.
CAUSE: VM workload -> CPU samples -> host policy -> pin target
DATA: domain.vcpu | cpuTime | memory | affinity
CORRECTION: cumulative time -> wrong load -> sample delta -> load estimate
INTERVIEWER TRAP: same total -> different periods -> false overload -> bad move
MANUAL CALCULATION: A counter growing from 8s to 9s over 2s equals 50% of one CPU, not 9 CPUs or 9%.
EVIDENCE STATUS: No exact course defect verified; source contract requires CPU-time deltas, not absolute totals.
PRIMARY/RELEVANT SOURCE: https://libvirt.org/html/libvirt-libvirt-domain.html
